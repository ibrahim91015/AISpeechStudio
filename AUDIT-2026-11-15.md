# Document and long-form audit — November 15, 2026

Scope: changes beginning with “the start of long-form import testing,” including 65 MiB uploads, 5 million imported characters, 600,000-character runs, range-based titles, priority between bulk runs, and durable audio assembly. No browser/computer control was used in this audit.

## Findings fixed

- Large scripts/books could exceed sessionStorage and silently lose drafts on navigation. IndexedDB now stores them, with a visible storage-failure warning and the existing manual-reload reset behavior.
- Long document parsing held a single proxy request open. Browser imports now use short receipt/status requests. Parsing runs separately with memory, CPU, disk, time and queue limits, and temporary files are cleaned up.
- Oversized multipart bodies were only checked after upload. Request-body limits now run before parsing, including streamed requests.
- Malformed range metadata and non-text form fields could cause server errors. Validation now safely rejects bad fields or falls back to ordinary batch titles. Negative range offsets from trimmed selections are handled.
- A large whitespace sequence could crash splitting. Splits now preserve annotations and combining marks where valid; pathological combining sequences are rejected. The displayed run count follows the server algorithm.
- Repeated submissions could queue duplicate books after a lost proxy response. Idempotency receipts and transactional insertion prevent duplicate batches.
- Some DOCX deleted paragraphs, text boxes, hidden runs and page fields could leak into speech. ODT comments, image frames and style text also needed exclusion.
- Ebook metadata labels were hidden without always removing their text. Cleanup now removes corresponding text and remaps all chapter/section/page offsets, retaining real preludes, introductions and epigraphs.
- The older the fantasy novel fixture EPUB stores its opening epigraph in an unlisted reading-order item before the Prologue navigation target. That epigraph is now retained.
- Legacy MOBI repeated book headings, illustration entries, preview excerpts and trailing credit lists needed additional cleanup.
- Untagged print PDFs needed conservative repeated-header/page-number removal and explicit publisher/duplicate-contents cleanup.
- Checkpoint validation and directory durability were tightened. An unload failure pauses queue consumption while cleanup retries; scratch-file cleanup errors no longer terminate the worker.

## Verification

39 Python regression tests passed on the server in an isolated checkout and temporary database. They cover all accepted file extensions, UTF encodings, Unicode offsets, malicious XML, malformed/oversized files, native/scanned/password-protected PDFs, exact upload/text boundaries, atomic batching, concurrent duplicate submissions, priority order, rollback, reference snapshots, import saturation/timeouts, chunk retry/rewind, cancellation, restart recovery, and audio export.

The common worker completed a full 600,000-character script using synthetic chunks, with no missing or duplicated non-whitespace characters. All seven model identifiers exercised WAV, MP3 and FLAC export paths with synthetic audio. This validates orchestration and assembly, not the inference quality of those models.

Node DOM/IndexedDB tests passed for the ebook-only picker, range selection, batch count, titles, selected-text submission, reuse of submission identifiers, 5-million-character draft retention alongside an ebook, model retention, reload reset, asynchronous import, filename titles, OCR warnings, script preservation after failure, and expired Pangolin-login messages.

All ten supplied documents were re-imported. The four most recent book files were checked for valid ordered UTF-16 ranges, preserved openings, and removed known metadata. the large EPUB fixture exposes 131 chapter entries including its prologue. Both the long book fixture ebook formats expose 87 entries including prelude/prologue/interludes/epilogue. the legacy MOBI fixture exposes 26 chapters without its repeated book-title headers. Both the fantasy novel fixture formats expose 40 entries including prologue/epilogue. The matching short-story PDF and DOCX have identical text after whitespace normalization.

## Practical limits

- the long book fixture PDF still explicitly reports 23 pages without a text layer. They are skipped by the sparse-image-page policy; this is not a claim that every PDF page contains no omitted text.
- OCR is bounded to twelve missing pages and a 35-second scanning allowance, with warnings for partial scans. Arbitrary scans and complex multi-column layouts still require reviewing the extracted script.
- No complete 600,000-character **real-model inference** was attempted. That would be a much longer workload than the synthetic assembly test.
- A signed-in upload through the real Cloudflare/Pangolin path still requires a manual browser check. Server/API tests cover trusted-origin behavior, asynchronous receipts and authentication-error handling; they cannot establish the behavior of an uninspected proxy rule or an expired browser session.
